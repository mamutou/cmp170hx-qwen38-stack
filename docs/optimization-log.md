# 优化时间线与死路清单

按时间顺序记录每一步"为什么改、改完多少、结论是什么"。**失败的路线和数字一并保留**——这部分比最终配置更省后来者的时间。

标注：`[本机]` = 本机实测；`[社区]` = 他人/厂商标称，仅作参照。

---

## 1. 基线选择：bf16 → W8A8 → W8A16（2026-08）

| 配置 | 解码 | 说明 |
|---|---|---|
| bf16（54GB 权重） | 22.6 tok/s `[本机]` | 64GB 卡能装但只剩几 GB KV |
| W8A8 int8（27GB） | 23.6 tok/s `[本机]` | 激活也量化，算力换不到速度 |
| **W8A16 int8 g128（30GB）** | **51.4 tok/s** `[本机]` | 权重 int8、激活 bf16；配合 MTP 才到 51 |

教训：在这张**算力受限**的卡上，降比特省的是内存不是时间——减字节不减运算；真正的跃升来自投机解码（下面的 MTP）。

## 2. MTP 投机（2026-08，收益最大的一步）

- 深度扫参：n=1 明显慢于 n=3；固定 **n=3**（思考链更短、TTFT 更稳）。
- 接受长度 3.02，逐位置 **0.855 / 0.651 / 0.518**，平均 67.5% `[本机]`。
- 坑：主线构建若不带 MTP 图会**静默忽略** head（日志里没有 `draft acceptance` 就是没生效）；head 在 `MTP/` 子目录时要显式指定。
- 副作用：预填 −20%（head 也要过 prompt）、显存 +2.5–3GB、并发 >1 时净亏（0.81–0.87×）。长文一次性预填的场景可临时关投机。

## 3. 稳定性优先的两个开关（2026-08-27）

| 开关 | 取值 | 原因 |
|---|---|---|
| `CUDAGRAPH_MODE` | **NONE** | 开 CUDA graph 时思考链出现 `!!!!` 重复；关掉后复现消失。代价 5–12% 解码，属于"用速度换可用性"的自觉选择 |
| `BATCH_TOKENS` | 16384 | 32768 时 KV 余量不足；固定 `--kv-cache-memory-bytes 30G` 直接 OOM |

采样侧同步加固：`presence_penalty 1.2 → 1.5`、`repetition_penalty 1.0 → 1.05`（Qwen 思考模式建议上限），`temperature 0.6 / top_p 0.95 / top_k 20`。

## 4. DFlash 草稿：实测否决（2026-10-24）

vLLM 0.27.1 的 registry 里确有 `DFlashDraftModel → qwen3_dflash`（`--speculative-config {"method":"dflash", ...}`），我们拿按 heretic-ara hidden 训的草稿（3.46GB）做同场对打：

| 配置 | conc1 解码 | conc4 解码/路 | conc4 合计 | 预填 | 接受长度 |
|---|---|---|---|---|---|
| **W8A16 + MTP k=3** | **51.4** | **52.2** | **202.7** | 1835 / 2536 | **3.02** |
| + DFlash `n=7` | 41.3 | 37.5 | 140.0 | 1631 / 446 | 2.38（接受率 19.6%） |
| + DFlash `n=3` | 37.2 | 35.1 | 132.3 | 1622 / 444 | 2.17（逐位置 0.62/0.44/**0.13**） |

机制：位 1–2 接受率还行（0.62/0.44），**位 3 直接崩到 0.13**；同时稠密 5 层草稿每个 cycle 都要完整前向一次，在算力被削的 GA100 上这笔开销比它省下的验证更贵。n=7 比 n=3 略快，是因为 7 位验证把草稿成本摊薄了，但仍追不上 MTP。

结论：**vLLM 只支持 DFlash v1（没有 DFlash2 arch）；这条路在本卡到此为止**，别再花时间调参。顺带记下端口坑：网关 `gpu-orch` 占 `:8080`，测变体要换端口（用 systemd 瞬态单元 + 8085），且别停网关（cron 每 5 分钟拉回）。

## 5. llama.cpp 路线（Flash-Next，2026-08~09，已退役）

在这张卡上跑 125B-A6B 级 MoE 的实测阶梯（GGUF，2K 提示）：

| 阶段 | 代码 | 散文 |
|---|---|---|
| 纯 AR 基线 | 53 tok/s | — |
| + MTP | 84 | 61 |
| + MTP + `ngram-map-k` | **96** | **70** |
| 单用 ngram（无 MTP） | 无收益 | −8% |

要点：
- 投机深度必须自扫：n=2/3/4 → 代码 **75.4 / 79.9 / 85.3**（散文 68.1 / 70.1 / 70.2），n=5 显存吃紧。
- `ngram-map-k4v` 接受率更高（95% vs 92%）但散文掉 9%：**接受率 ≠ 吞吐**，草稿本身也花算力。
- `-np` 切的是"每流上下文 = `-c` ÷ slot"，并发不提高总吞吐；`-np 1 + n=4` 反而比 `-np 4 + n=2` 高 8–11% 且少 1GB 显存。
- 后来整条路线被 Strata 取代（脚本已 `exit 1` 退役）。

## 6. Strata 路线（2026-09~10，现役）

1. 量化档上限由**主机内存**决定，不由显存：IQ3_S 专家 46.84GB（内存占 52GB，解码 109 `[社区+本机折算]`）；UD-IQ4_XS 专家 55.43GB → 可用内存归零、开始 swap、解码 −17%；UD-Q4_K_XL 需 70–79GB，起不来。
2. 给共租负载腾内存：`--resident-experts`（专家转文件映射）→ 可用内存 0→37GB、解码只 −0.7%、冷启动 36→52s；`--memory-limit-mib` 实测**无效**；`--mmap-experts` 只有 ~29 tok/s（不要用）。
3. 并行：`parallel=4` 会为 KV 缩小 GPU 专家缓存（24576→19874 专家、46.84→37.86 GiB），单请求 −9%，剩余显存只剩 162MB → 4 条长上下文必 OOM。生产用 `parallel: 2`。
4. 最终 profile：UD-IQ4_XS pack + `--spec 4` + MTP + `--kv int8 --kv-grow` + `--resident-experts` + `--adapt-async 1`。实测解码 p50 85 / p90 102.5 tok/s，专家缓存 p50 99.2% 命中。

## 7. 引擎选型结论

| 引擎 | 能否跑 27B | 判定 |
|---|---|---|
| **vLLM 0.27.1** | ✅ 现役 | 唯一"零改动"可跑 W8A16+MTP 的；下一步是 int4 |
| SGLang 0.5.18 | ⚠️ 架构有（`qwen3_5.py` + GDN + `is_nextn`），但压缩方案只有 **W8A8-int8 / W8A16-fp8 / W4A4 / WNA16**，**没有 W8A16-int8** | 想用必须换 int4（GPTQ/AWQ+Marlin）权重；收益点在预填/并发，单流解码通常 ±10% |
| llama.cpp | ❌ 本机已退役 | 独占价值是 MTP+ngram 双投机叠加，对稠密 27B 增益远小于 MoE |
| Strata | ❌ 指纹表 17 条无此稠密模型 | 它的价值在专家缓存，对稠密模型无意义 |
| TensorRT-LLM | ⚠️ 理论可行 | 融合 kernel 上限最高，但 hybrid GDN 要自写 plugin、工程量以天计；算力被削的卡上约 +10~20% |
| ExLlamaV3 | ⚠️ 有现成 EXL3 3.5bpw 权重 | 单流 decode 内核强，但**无 MTP 投机**，很难超过 vLLM+MTP |

## 8. 剩下的动作（按性价比）

1. **int4 W4A16 + MTP 3**：每步少读 10GB，预期 65–80 tok/s。HF 上现成的 W4A16 / GPTQ-Int4 仓库都保留了 15 个 MTP 张量，vLLM 加载路径与现有 W8A16 同族。
2. **MTP 深度 3 vs 4**：零成本，第 4 位接受率仍有 0.518。
3. **CUDAGRAPH FULL**：+5~12%，须先复验 `!!!!` 重复率。
4. 若要压并发/预填，再评估 SGLang + int4（需另下/另转权重）。

## 9. 死路清单（别重跑）

| 尝试 | 结果 | 机制 |
|---|---|---|
| DFlash 草稿（n=7 / n=3） | 51.4 → 41.3 / 37.2 tok/s | 位 3 接受率 0.13 + 草稿每 cycle 完整前向 |
| 单用 ngram（不叠 MTP） | 散文 −8% | 草稿算力开销 > 命中收益 |
| IQ3_S → IQ2_XS | 只为内存，速度不变 | 减字节不减运算 |
| 更高 bpw（IQ4_XS 相对 IQ3_S） | 解码 −17%，降并行也追不回 | 反量化+乘加是纯成本 |
| `--memory-limit-mib` | 无效果 | 参数不控制内存驻留 |
| `--mmap-experts` | ~29 tok/s | 每 token 走页缓存随机读 |
| `--spec 5/6` | 显存吃紧、无收益 | 深度收益在 4 到顶 |
| GPC VF offset +250 | Xid 13 非法指令，context 被杀 | 本卡耐受度低于参考卡 |
| 4 卡 TP 提解码 | 不线性 | decode 受带宽/算力单卡限制 |
| 并发提总吞吐 | 4 路合计 ≈ 单路天花板 | 算力饱和，每 token 一份开销 |
| `--kv-cache-memory-bytes 30G` + batch 32768 | 启动 OOM | 峰值 activation 更大 |
